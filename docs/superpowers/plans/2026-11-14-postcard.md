# Field Notes Postcard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web app that turns a photo into a "rubber stamp field notes" postcard: the app crops and joins, Gemini (via the `agy` CLI) draws only the paper panel with the stamp, and the result is downloaded or scheduled by email.

**Architecture:** One Node/Express server on the Mac serves static pages and one JSON API. The server crops the photo with `sharp`, calls `agy` for the paper panel, prints the text, joins the two parts. Scheduled email is handed to a Google Apps Script web app. `shared/layout.js` (already written) holds all geometry and is imported by both server and browser.

**Tech Stack:** Node 26 (ES modules), Express, multer, sharp, node:test. Plain HTML/CSS/JS front-end. Google Apps Script.

**Spec:** `docs/design.md`

## Global Constraints

- No paid services, no API keys for generation. Images only through `agy`.
- `"type": "module"` in package.json. No front-end framework, no build step.
- All geometry, colours, text casing and text positions come from `shared/layout.js`. Do not duplicate numbers from it; do not edit it without telling the reviewer.
- Each task touches only its own files (listed per task). No git commits: the owner approves commits.
- The photo region of the result contains the user's own pixels, cropped and resized only.
- Server listens on `http://localhost:3000` (env `PORT` overrides).

## Review Focus

1. Phone photo with EXIF rotation → orientation and crop use the rotated dimensions.
2. `agy` returns a panel in the wrong ratio (e.g. 16:9, 1:1, 9:16) → centre-cropped to the exact ratio; result still exactly 1:1 or 5:4.
3. `agy` fails, times out, or no image file appears → HTTP 502 with a readable `error`; form contents kept; Retry works.
4. Small photo (e.g. 800×600) → result scaled down via `outputScale`, never upscaled more than 2×.
5. Email chosen but Apps Script not configured or it rejects → the postcard is still returned, with `emailError` set and shown.

## HTTP contract (Tasks 1 and 2 both rely on this)

- `GET /api/config` → `{ "emailEnabled": boolean }`
- `POST /api/postcards` (multipart/form-data): `photo` (file, required), `location` (required), `keywords` (optional, comma-separated, up to 3), `month` (one of `MONTHS`), `year` (4 digits), `delivery` (`download` | `email`), and when `email`: `email`, `sendDate` (`YYYY-MM-DD`, today or later), `message` (optional).
  - 200 → `{ "id": string, "imageUrl": "/results/<id>.jpg", "keywords": string[3], "scheduled": null | { "email": string, "sendDate": string }, "emailError": null | string }`
  - 400 (bad input) / 502 (generation failed) → `{ "error": string }`
  - The request stays open until the postcard is ready (up to ~6 minutes).
- `GET /results/<id>.jpg` → the postcard. `GET /fonts/SpecialElite-Regular.ttf` → the font. `GET /shared/layout.js` → the shared module. `/` → `public/index.html`, `/create` → `public/create.html`.

## Apps Script contract (Tasks 1 and 3)

- Server POSTs JSON to `APPS_SCRIPT_URL`: `{ secret, recipient, sendDate, message, location, filename, imageBase64 }` (follow redirects).
- Response JSON: `{ "ok": true }` or `{ "ok": false, "error": string }`.
- `.env`: `APPS_SCRIPT_URL`, `APPS_SCRIPT_SECRET`. Email is enabled only when both are set.
