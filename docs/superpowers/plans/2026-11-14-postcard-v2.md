# Postcard v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Nine owner-requested changes: real example postcards, a one-screen-per-section landing page with an interactive postcard wheel and an anatomy section, motion, faster generation, a staged loading page, a full-screen result page, and location/date read from photo metadata.

**Architecture:** Generation becomes a background job with named stages that the browser polls. Three pages replace the single create flow: `/create` (form + preview) → `/making?id=` (loading) → `/postcard?id=` (result). A metadata endpoint reads EXIF and resolves GPS to "City, Country" offline.

**Spec:** `docs/design.md` plus the owner's nine points (quoted in each task brief). Visual system unchanged (`public/css/base.css` tokens).

## Global Constraints

- Everything in the v1 plan's Global Constraints still holds: no paid services or API keys, no framework, no build step, no external CDN, geometry only from `shared/layout.js`.
- No git commits. Each task touches only its own files.
- Never run two `agy` processes at once (the image is found by "newest file", so concurrent runs can swap results). Before any real generation: `pgrep -fl agy` must show nothing running.
- Do not use Gemini Flash models.
- Honour `prefers-reduced-motion` everywhere: no scroll or hover motion, wheel changes without animation.

## HTTP contract v2

- `POST /api/metadata` (multipart `photo`) → `{ "location": "City, Country" | null, "month": "Nov" | null, "year": "2026" | null }`. Never fails on a readable upload; unreadable → all null.
- `POST /api/postcards` (multipart, fields as v1) — `location`, `month`, `year` are now optional. For each one left blank the server uses the photo's metadata; if that is missing too, that text line is omitted. Returns **202** `{ "id": string }` immediately. 400 `{error}` for bad input as before.
- `GET /api/postcards/:id` →
  `{ "id", "status": "working" | "done" | "error", "stage": "preparing" | "drawing" | "printing" | "finishing", "elapsedMs": number, "error": null | string, "result": null | { "imageUrl", "width", "height", "orientation", "location", "keywords": string[], "month", "year", "scheduled": null | {email, sendDate}, "emailError": null | string } }`; 404 `{error}` for an unknown id. A finished postcard stays readable after a server restart (small JSON saved beside the JPEG).
- Stages, in order: `preparing` (read, rotate, crop) → `drawing` (Gemini draws the stamp; the long one) → `printing` (text) → `finishing` (join, save, schedule email).
- Pages: `/` , `/create`, `/making` → `public/making.html`, `/postcard` → `public/postcard.html`. Existing static routes unchanged.

## Motion contract (Task C provides, Task B uses)

`/js/motion.js` (module, self-initialising) and `/css/motion.css`:
- `data-reveal` on an element: fades/slides in when scrolled into view (optional `data-reveal-delay="120"` ms).
- `data-tilt` on an element: gentle 3D tilt following the pointer, with a soft lift; resets on leave. Pointer-fine devices only.
- Elements added later are picked up (MutationObserver) or via exported `initMotion(root)`.
